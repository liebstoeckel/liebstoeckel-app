The audience joins from a phone (scan QR → vote / ask / react), so the **viewer is a first-class mobile surface**. The challenge: interactive controls live inside the fixed, scaled canvas, where on a portrait phone they'd shrink to ~30%. liebstoeckel solves this without breaking the fixed-canvas guarantee.

## The phone view for the audience

When someone in the audience holds a phone upright (a touch screen in portrait, up to 560 px wide) and the presenter is on a slide with an interactive plugin, the phone switches to a layout made for voting:

- **The slide as a strip** at the top, full width. The plugin's place on the slide shows its name and an arrow down.
- **The plugin below it, full width, at the phone's own scale.** Poll options are real buttons: one tap votes. Several plugins on one slide stack in the order they are placed.
- **The bottom row stays clear.** The menu, the reactions button, the slide counter and a "Published with liebstoeckel" badge sit below the plugin area, never on top of it.
- **Typing gets the room it needs.** When the ask box of a Q&A has focus, the plugin area takes the whole screen; it gives the strip back when the keyboard closes. A half typed question is still there if the presenter moves on and comes back.
- **When the talk ends,** the plugin area dims, stops taking taps and says so.

On a slide without an interactive plugin the phone shows the slide as usual. The presenter on a phone, a phone held sideways, a tablet and every desktop window keep the slide as authored, with the breakout below. Nothing about this needs setting up: every `<Plugin>` whose plugin takes input (`client.interactive`, true by default) gets it.

<Aside type="tip" title="Preview it before the talk">
Start the deck live (`liebstoeckel live`), open the audience link in your browser's device emulation (a phone in portrait with touch, for example Chrome DevTools' device toolbar), and move to a slide with a plugin from the presenter window. The emulated phone shows what the room will see.
</Aside>

## Tap-to-interact breakout

On a touch device with a shrunk stage (the presenter's phone, a phone held sideways), a `<Plugin>` doesn't try to make tiny controls tappable. Instead it:

<CardGrid>
  <Card title="Glows" icon="star">
    The whole plugin region gets a pulsing brand-accent outline and a "tap to interact" pill (a large, easy target).
  </Card>
  <Card title="Breaks out" icon="external">
    Tapping opens the same plugin **full-size in a bottom sheet** rendered *outside* the scaled canvas: real tap targets, bound to the same live state.
  </Card>
</CardGrid>

This is built into the engine's `<Plugin>` component, so **every** plugin (poll, Q&A, reactions, and your own) inherits it. It engages only when the pointer is coarse **and** the stage is scaled down **and** a live server is connected.

<Aside type="tip" title="Opting out">
Display-only plugins (no input) should set `client.interactive = false` so they don't show a misleading "tap to interact" affordance. See [Building a plugin](/plugins/building-a-plugin/).
</Aside>

## Touch navigation

For whoever drives the deck (a standalone viewer or the presenter; a live audience viewer just follows), the engine binds **horizontal swipe** and **edge tap-zones** to advance/retreat, reusing the same step-then-slide logic as the keyboard. Gestures that start on interactive content (buttons, links, the plugin region) are ignored so they never fight the UI.

## Portrait hint

On a portrait phone the 16:9 slide is letterboxed. A dismissable "rotate for a bigger view" hint nudges the viewer; it's rendered at device scale (outside the canvas) and auto-hides. It stays away while the phone view shows a plugin.

## Presenter view on a phone

On a phone the presenter view is a **notes-first confidence monitor** you can run a whole talk from. Open it from the deck's **⋮ menu → "Presenter view"** (the touch counterpart to the desktop <kbd>p</kbd> pop-out; shown only to drivers, never to a live viewer). It's handy after scanning the "drive from your phone" presenter QR.

The layout puts your **notes front and centre** (large and scrollable: the teleprompter), with a slim status bar (position + timer), a compact next-slide + reveal-state peek, and big **Prev / Next** buttons in the thumb zone. Swipe horizontally to change slides; scrolling the notes never advances them (the gestures are resolved by axis). The screen is kept awake via the Wake Lock API while it's open, and **"‹ slides"** returns to the deck.

<Aside type="note" title="Threat model unchanged">
Mobile support is UX/layout only: no change to sync or security. A live viewer still only reads the deck index and writes its own plugin state.
</Aside>
