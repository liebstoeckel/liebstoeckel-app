A standalone deck syncs across your own windows via `BroadcastChannel`. Run it through the **live server** and it becomes a shared session: every connected device follows along, and [plugins](/plugins/overview/) come alive.

## Start a session

```bash
liebstoeckel live my-talk            # a deck dir, or a built .html
```

This builds the deck (if needed), serves it on your LAN, and prints presenter + audience links:

```
▶  liebstoeckel live, session a1b2c3d4
   on this machine   presenter  http://localhost:4321/?t=…
                     audience   http://localhost:4321/?t=…
   on the network    presenter  http://192.168.1.20:4321/?t=…
                     audience   http://192.168.1.20:4321/?t=…
```

<Steps>

1. Open the **presenter** link (or press <kbd>p</kbd> for the presenter window).
2. The room opens the **audience** link: the presenter's deck shows the [join card](#the-join-card) on its own when the talk starts, <kbd>q</kbd> shows it again at any time, or share the link directly.
3. Navigate: every viewer follows. Plugins (polls, Q&A, reactions) sync in real time.

</Steps>

## The join card

The join card is how the room gets in: a QR code of the audience link, the link itself, and,
on the presenter's screens, how many people are watching.

- **When the talk starts.** The presenter's deck window opens the join card full-screen by
  itself when a live session loads on the first slide. The first <kbd>→</kbd> (or a click,
  or your clicker) only puts it away; the next one advances. It also goes away when the
  slide changes from anywhere else, such as the presenter window or your phone. It does not
  open by itself on a reload in the middle of a talk, on a phone, or when the first slide
  already has a `<JoinCard />`.
- **At any time.** Press <kbd>q</kbd> in the deck window.
- **The count.** "Waiting for people to join", then "12 watching". It counts open
  connections, so a phone with the link open in two tabs counts twice. The deck window,
  the one the room sees, never says more than that; the presenter window and the
  dashboard also tell you when the session is full.
- **In the presenter window** the header shows the count as a small pill; click it (or press
  <kbd>q</kbd>) for the share screen.

In the cloud the link is the session's short, stable link (`…/live/k7m2x9qp4r`), which keeps
working if the session moves to another server mid-talk. On a self-hosted
[relay](/guides/relay/) it is the relay's audience link with a signed token, and on your LAN
the `liebstoeckel live` audience link.

### `<JoinCard />` on a slide

Place the card on a slide yourself, for example on the title slide or a "questions?" slide:

```tsx
import { JoinCard } from "@liebstoeckel/engine";

export default function Title() {
  return (
    <div className="flex h-full w-full items-center justify-between gap-16">
      <h1 className="text-7xl">Present with the room</h1>
      <JoinCard size={300} />
    </div>
  );
}
```

| Prop | Default | |
| --- | --- | --- |
| `size` | `280` | QR size in pixels on the 1920×1080 stage; the link scales with it |
| `label` | `"Scan to join"` | the line above the QR; `""` for none |
| `fallback` | a placeholder | what to show without a live session; `null` shows nothing |

Without a live session (the deck opened as a plain `.html`, a thumbnail, a PDF export) the
card keeps its space and says the join code appears there when the deck is presented live,
so the slide's layout holds. A first slide with a `<JoinCard />` keeps the deck from opening
the full-screen card by itself. Viewers see the card too (handy for passing the link on),
without the count.

<Aside type="tip" title="Drive from your phone">
In the presenter window (<kbd>p</kbd>), press <kbd>q</kbd> (or the header QR button) to open the share screen. It shows the join card (the audience link) and a **Drive from your phone** button. Only after you click it does the presenter QR appear; scanning it joins your phone as a second driver, handy for advancing slides while you walk the room. Anyone who scans that code can control the talk, so reveal it only on a screen the room can't see. It hides again when you close the share screen. The <kbd>q</kbd> overlay in the deck window, the one you project, only ever shows the audience QR.
</Aside>

<Aside type="tip" title="Presenter consoles & focus mode">
The presenter window's panel is **tabbed**: **Notes** (default) plus a private console per interactive plugin. Watch live poll tallies, or moderate the Q&A queue (mark answered, dismiss, reveal) without any of it showing on the room's screen. When a pane gets busy, press <kbd>z</kbd> (or the ⤢ button) to **maximize** it: the slide previews hide while navigation and the talk timer stay pinned; <kbd>Esc</kbd> restores.
</Aside>

## Roles & sync

State lives in a **Yjs** document (a CRDT) shared over WebSocket. A small relay (`Hub`) keeps one doc per session and broadcasts changes.

- **Presenter**: drives the slide index; everyone follows. Can moderate plugins.
- **Viewer**: follows the presenter's index; can still interact with plugins (vote, ask, react).

Roles come from an **unguessable token in the link** (`?t=…`), not a login. On a
[relay](/guides/relay/) or in the cloud, a presenter link's token leaves the address bar
on the first load: the relay keeps it in a cookie for that page and redirects to the
same address without it, so a projected or screen-shared presenter tab shows nothing
that grants control, and a reload or the <kbd>p</kbd> pop-out still opens as the
presenter. The cookie lasts until you close the browser; after that, open the presenter
link again. Audience links keep their token, since they are meant to be shared. Each
audience browser is one participant there: a reload or a second scan of the QR code keeps
its vote, and the address copied to another device is a new participant (see
[untrusted-HTML isolation](/guides/relay/#untrusted-html-isolation) on the relay page). A viewer's
client is scoped to match: the **presenter view** (<kbd>p</kbd> / `#presenter`) and the
**overview grid** (<kbd>o</kbd>) are presenter-only: they stay disabled and dimmed in the
shortcut help (<kbd>?</kbd>) for viewers, so the speaker notes and plugin consoles aren't
reachable from a shared audience link.

### What the audience sees

Every window reconnects by itself after a network drop or a server restart, and sends
what it changed while it was away. In the cloud a talk can also move to another server
mid-session (a restart or an update of the servers): votes, questions and reactions sent
just before the move still arrive, and someone opening the audience link during it gets
the talk.

The presenter sees every problem with the connection as a small status in the corner:
**Reconnecting**, **Offline**, or **Talk ended** once the session is over. The audience
sees only what matters to them, so a short server restart does not flash on every phone
in the room:

| State | What a viewer sees |
|---|---|
| **Offline** (the device has no network) | A line in the corner: *Offline. What you send goes out once the connection is back.* A vote made now says *Sending your vote* instead of *Vote received*, and goes out on reconnect. |
| **Reconnecting** for longer than about 5 seconds | *Reconnecting* in the corner, until the connection is back. Shorter drops show nothing. |
| **Session full** (the audience cap is reached) | A full-screen card: *This session is full*, with a suggestion to follow on the main screen and a **Try again** button. The page does not keep knocking by itself. |
| **Talk ended** (the presenter ended the session, or its time ran out) | A card: *The talk has ended. Thanks for joining.* **Back to the slides** shows the deck as the talk left it, with what the plugins showed (a poll's results, if its `results` setting shows them to that viewer). Nothing can be sent any more. |
| **Out of date** | *Out of date, reload* in the corner, when the page is older than the server it talks to supports. A reload loads a current one. |

In the cloud, the audience link (`/live/<code>`) answers with a small page of its own when
there is no talk to show: **No live session at this link** (check the code), **The talk
has ended**, or **Waiting for the session** while it is being started again (that page
checks again by itself every few seconds). A reload of an audience tab after the talk
ended says **This talk isn't running**.

### Languages

Everything above, and what the poll, Q&A and reactions say to the audience, is in English
and German. Each viewer gets the language of their browser (German if it prefers German,
English otherwise). Add `?lang=de` or `?lang=en` to the audience link to choose one for
everyone who opens it, for example in the link you put on a slide or send to a meeting.
The German never addresses the reader as "du" or "Sie", so it fits a team meeting and a
conference alike. The slides themselves are yours and are shown as written.

### When a session is full

There are two kinds of full. The **audience cap** limits how many people can join at once
(in the cloud it comes with your plan; on your own [relay](/guides/relay/), whoever
creates the session can set one). Someone who opens the link above it gets the *session is full* card
above and can try again once someone leaves.

Through the relay, audience input has limits too (see [limits on audience
writes](/plugins/state-and-sync/#limits-on-audience-writes)), and the relay pauses it
while it is short of memory. When a vote, question or reaction is refused, the viewer
sees it undone on their screen and a short message saying it didn't reach the
presenter, and why: the session is full, or the live server is busy and they can try
again in a moment. A refused question goes back into their ask box.

While input is being refused, the presenter view shows a banner: **Audience input is
paused**, with the reason. It goes away once audience input arrives again. The banner
is only on the presenter's screen, never on the projected slides.

## Where code runs

<Aside type="caution" title="Decks are trusted">
Building and running a deck executes its code, including any **server plugins**, on *your* machine. A trust warning is printed before a deck loads. Only run decks you trust.
</Aside>

- A plugin's **client** part does WS + shared-state only and runs in every browser.
- A plugin's optional **server** part runs **once**, on the machine that started `liebstoeckel live`, never in the audience's browsers.

## Going beyond the LAN

`liebstoeckel live` is LAN-first. To reach viewers over the public internet, point it at a **relay**:

```bash
liebstoeckel live my-talk --relay https://relay.example.com --relay-token <token>
```
