## The fixed canvas

Every slide is authored on a logical **1280×720** canvas (`STAGE_W × STAGE_H`). The engine's `ScaledStage` scales that canvas to fit any screen, centered and letterboxed, so a slide looks identical on a laptop, a projector, and a phone (just at a different scale). You never write responsive breakpoints for slide content. You design once at 1280×720.

`SlideFrame` gives each slide a padded content area over the deck's backdrop (by default a static brand-colored atmosphere; configurable with the `backdrop` prop on `Present`). Break out with absolute positioning for full-bleed visuals.

## Themed MDX elements

In MDX you write plain Markdown and the look comes from the brand. The mapping (in `@liebstoeckel/components`):

## Persistent stateful elements

[Magic Move](/guides/your-first-deck/#magic-move) re-renders content, which would reset a stateful element (an `<iframe>`, a `<video>`, a running widget). For those, the engine provides a **persistent layer**: render the element once at the deck root and project it into slides via a `<Slot>`. It keeps its internal state while traveling between slides.

The two are complements: `Magic` morphs *different stateless elements* into one another (declared inline per slide); `<Slot>` carries *one stateful element* across slides (defined once). Reach for `<Slot>` when state must survive, `Magic` for a stateless flourish.

```tsx title="main.tsx"
<Present
  slides={[...]}
  persistent={[{ id: "live", render: () => <LiveIframe /> }]}
/>
```

```mdx title="a slide"
import { Slot } from "@liebstoeckel/engine";

## The clock keeps running →

<Slot id="live" className="mt-10 h-56 w-full rounded-2xl border border-surface" />
```

Move the `<Slot id="live">` to a different position on the next slide and the live element animates to its new home without reloading.

### How it behaves between slides

The element is positioned onto the slot on the **current** slide, and how it gets there depends on where you came from:

- **Travel**: both the slide you left *and* the one you entered have a `<Slot>` with the same `id`. The element **springs** from the old position/size to the new one, state intact. This is the headline trick: put the slot in two consecutive slides at different spots to make a live widget glide across.
- **Appear**: you arrive from a slide that has **no** matching slot (or it's the first time it shows). The element **snaps** into the slot and only fades in. It won't fly in from wherever it last was.
- **Leave**: the next slide has no matching slot. The element **fades out in step with the slide transition** (it doesn't linger after).

It's positioned in the deck's logical canvas space, so it lines up with the slot at any stage scale (fullscreen, windowed, or mobile). Reloading is never triggered by any of these: the element is rendered once and never unmounts.

## Slide transitions

How one slide gives way to the next is configurable. Set a deck-wide default on `Present`, and override any individual slide with an `export const transition`:

```tsx title="main.tsx"
<Present slides={[...]} transition="slide" />   {/* deck default; omit for "fade" */}
```

```tsx title="a slide"
export const transition = "zoom";               // this slide only
```

Built-in presets: **`fade`** (default), `blur`, `slide` (directional push, mirrors on back-nav), `zoom`, `none`. Need something bespoke? Pass a custom spec instead of a name:

```tsx
export const transition = {
  variants: { enter: { opacity: 0, y: 40 }, center: { opacity: 1, y: 0 }, exit: { opacity: 0, y: -40 } },
  transition: { duration: 0.5 },
};
```

Transitions respect `prefers-reduced-motion` (they collapse to a tiny fade), and don't affect persistent-layer elements: those travel above the swap untouched.

On **mobile** (touch / coarse pointer) transitions are **off by default**. The stage is heavily down-scaled there, so cuts feel snappier and avoid jank. Opt back in with the `mobileTransitions` escape hatch:

```tsx title="main.tsx"
<Present slides={[...]} transition="slide" mobileTransitions />
```

## The deck's backdrop

Behind every slide sits the deck's **backdrop**, rendered once per view behind the transition stack, so a slide change crossfades the content over a stable background. Omit the `backdrop` prop on `Present` for the default atmosphere, pass `null` for a flat background, or pass your own component:

```tsx title="main.tsx"
<Present slides={[...]} backdrop={Sky} />
```

The engine hands it three kinds of props:

- **`still`** is set on thumbnails, the overview, print, capture and the presenter's previews. Render a motionless, deterministic frame there.
- **`slide`** is the 0-based index of the slide it is drawn behind: the current slide in the deck, the shown slide in a thumbnail or preview. Use it for what follows the talk's progress.
- **Its own props**, which a slide sets with `export const backdropProps`. They reach the backdrop wherever it is drawn behind that slide, in the deck and on every still surface, and they stay with the slide when you reorder the deck.

```tsx title="elements/Sky.tsx"
import type { BackdropComponent } from "@liebstoeckel/engine";

export type SkyProps = { palette?: "night" | "dusk" };

// motionless, so it needs nothing from `still`
export const Sky: BackdropComponent<SkyProps> = ({ slide = 0, palette = "night" }) => (
  <div className="absolute inset-0" style={{ background: palette === "dusk" ? "#2a1408" : "#06121f" }}>
    {/* the moon climbs one step per slide */}
    <div
      className="absolute right-24 top-[460px] size-12 rounded-full bg-[#f4f1e4]"
      style={{ transform: `translateY(${-slide * 40}px)` }}
    />
  </div>
);
```

```tsx title="a slide"
import type { SkyProps } from "../elements/Sky";

export const backdropProps: SkyProps = { palette: "dusk" };   // this slide only
```

```tsx title="main.tsx"
import * as dusk from "./slides/05-dusk";   // a namespace import carries backdropProps

<Present slides={[intro, dusk, outro]} backdrop={Sky} />
```

The engine reads `backdropProps` from the slide's module, as it reads `notes` and `transition`, so import that slide as a namespace (`import * as`). A default import passes only the component, and the export is dropped without a warning. Annotate the export with the backdrop's props type, as above: the engine can't check a slide's values against the backdrop for you.

Every prop of your own must be optional, since a slide without `backdropProps` passes none. The values are static: the engine reads them with the slide, so a slide can't change them while it runs. In the deck, the backdrop gets the next slide's props as soon as the slide changes, while the old slide is still fading out; if the change should be gradual, animate it in the backdrop (a CSS transition on `transform` or `opacity` costs nothing per frame).

The repository's `presentations/backdrop-demo` deck is a complete example: an aurora that animates at near-zero CPU, a moon that climbs with `slide`, and a slide that warms the sky through `backdropProps`.
