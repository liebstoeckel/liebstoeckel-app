Everything below is from `@liebstoeckel/engine` unless noted.

## Top-level

| Export | Kind | Purpose |
| --- | --- | --- |
| `Present` | component | the entry; routes to Deck / PresenterView / CaptureView |
| `Deck` · `DeckProps` | component | the audience/standalone view |
| `PresenterView` | component | the `#presenter` window |
| `CaptureView` | component | build-time thumbnail render |
| `normalizeSlides` · `SlideInput` | fn / type | normalize slide modules |

## Authoring

| Export | Kind | Purpose |
| --- | --- | --- |
| `Step` | component | a progressive reveal |
| `StepsProvider` | component | per-slide step tracker (the engine mounts this) |
| `useRevealState(count)` | hook | claim `count-1` reveal slots, get the active state index (for `CodeMagic`-like components) |
| `CodeMagic` | component | animated code; `steps`, `title?`, `lang?` |
| `TokenizedStep` · `CodeToken` | types | the tokenized code states a `.code.md` import gives |
| `Magic` | component | Magic Move via shared `layoutId` |
| `Atmosphere` | component | the default backdrop: static gradient blooms + vignette (`still?`, opt-in `drift?` via CSS keyframes, honors `prefers-reduced-motion`) |
| `Present`/`Deck` `backdrop` prop | prop | deck-wide decoration behind the slide transition stack: omit for `Atmosphere`, `null` for a flat background, or a component receiving `still?` (it must render motionless when set: thumbnails, print, capture, presenter previews), `slide?`, the 0-based index of the slide it is drawn behind (the current slide in the deck, the shown slide in a thumbnail or preview), and the props that slide sets with `export const backdropProps` (each one optional) |
| `Backdrop` · `BackdropProvider` · `BackdropComponent<P>` | component/type | the resolved backdrop of the current deck (custom views render `<Backdrop still slide={i} />` themselves; `BackdropProvider`'s `slides` supplies each slide's `backdropProps`, and without `slides` it keeps an outer provider's, while a missing `backdrop` still means the default `Atmosphere`); `P` types a backdrop's own props |
| `Present`/`Deck` `transition` prop | prop | deck-wide slide transition; a slide can `export const transition` to override |
| `Present`/`Deck` `mobileTransitions` prop | prop | re-enable slide transitions on mobile (coarse pointer); off by default |
| `Present`/`Deck` `brands` prop | prop | brand names to theme the deck with; the first is active, <kbd>t</kbd> cycles the rest. Defaults to `["liebstoeckel"]`; in development a name with no theme behind it logs a console warning (see [theming](/guides/theming/)) |
| `Present`/`Deck` `brandThemes` prop | prop | `Theme[]` of deck-defined brands, injected as `[data-brand]` CSS; reference by `name` in `brands` (see [theming](/guides/theming/)) |
| `resolveTransition` · `TRANSITIONS` · `DEFAULT_TRANSITION` | fn/const | resolve a name/custom spec → Motion variants; the built-in presets; the default (`"fade"`) |
| `SlideTransition` · `SlideTransitionName` · `SlideTransitionSpec` · `SlideDirection` | types | transition config (preset name `fade`/`blur`/`slide`/`zoom`/`none`, or a custom `{ variants, transition }`) |
| `Slot` · `PersistentProvider` · `PersistentLayer` · `PersistentItem` | components/type | persistent stateful elements |

## Live & plugins

| Export | Kind | Purpose |
| --- | --- | --- |
| `Plugin` | component | place a plugin (`id`, `props?`, `components?`) |
| `LiveProvider` · `useLive` · `LiveContextValue` | component/hook/type | the live context (with `connection`, the live connection's state, and `synced`, whether the session state has arrived) |
| `detectLive` · `LiveInfo` | fn/type | is a live server connected? |
| `connectLive` · `LiveConnection` | fn/type | connect to a session over WebSocket; `onStatus` (connected or not), `onState` (`LiveState`) and `synced` / `onSynced` (the session state has arrived) |
| `LiveState` · `LiveStatus` | types | `connecting`, `connected`, `reconnecting`, `ended`, `full` (the session is at its audience cap; the client does not retry by itself), `outdated` (with the server's message) |
| `LIVE_CLOSE` · `LIVE_PROTOCOL` · `withLiveProtocol` | consts/fn | the live socket's close codes and protocol version |
| `useLiveDeck` · `getDeckIndex` · `setDeckIndex` · `DeckController` | hooks/fns/type | the synced slide/step controller |
| `getParticipantId` | fn | stable participant id: the one the hosting relay issued (kept in its cookie, so it stays with the browser; a `?pid=` left in the URL is removed), else per tab: a `?pid=` in the page URL first, then `sessionStorage`, else a new one (written into the tab's URL when storage is blocked, so a reload keeps it) |
| `mergeUi` | fn | merge author surface overrides |

## Navigation & delivery

`useDeckNav` (keyboard) plus pure helpers: `stepForward`, `stepBack`, `clampIndex`, `accumulateDigits`, `fullscreenAction`, `toggleFullscreen`.

## Thumbnails (runtime)

`readThumbnails()` → `ThumbnailSet | null`: the embedded thumbnail manifest, used by the overview grid.

## Build subpaths

| Import | Exports |
| --- | --- |
| `@liebstoeckel/build` | `bundleDeck` (the browser-free single-file build), `checkDeck` (does it build? structured diagnostics), `collectDeckLicenses`, `buildPluginManifest`, `buildServerBundle`. Options as before, plus `profile` and `log` |
| `@liebstoeckel/build/dev` | `createDeckDev({ deckDir, base })`: the dev server as a `fetch` handler plus a WebSocket handler for `Bun.serve`, the one `liebstoeckel dev` mounts |
| `@liebstoeckel/engine/build` | **deprecated**: the Bun pipeline `bundleDeck`, `checkDeck`, `collectDeckLicenses` (`Bun.build` with Bun plugins), kept one release for a `build.ts` that calls it. Use `@liebstoeckel/build` |
| `@liebstoeckel/engine/code` (macro) | **deprecated**: `codeStory`, `code` (import `with { type: "macro" }`); the build reads their literal arguments. Use a [code file](/guides/animated-code/) |
| `@liebstoeckel/engine/build/thumbnails` | `embedThumbnails`, `extractThumbnails`, `stripThumbnails` (the manifest format) |
| `@liebstoeckel/engine/build/visual-audit` | `auditSlideDom`, the self-contained check behind `build --check --visual` (text cut off by its box, chart labels clipped by their svg, text off the stage), for running in a page that renders one slide at the stage size |
| `@liebstoeckel/thumbnails` | `withThumbnails` (gated, never-fatal capture+embed), `captureThumbnails`, `addThumbnailsToFile`, `thumbnailsEnabled` |
| `@liebstoeckel/thumbnails/build` | `buildDeck`, **the default build**: `bundleDeck` + slide thumbnails |
